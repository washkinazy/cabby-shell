# Clipboard

Cabby owns regular clipboard history in the existing coordinator. The picker is a built-in desktop plugin using the shared panel slot, placement, keyboard focus, dismissal and theme. No additional daemon, binary or service is installed.

Click the clipboard icon (included before the tray in the default right bar), or run `cabby clipboard`. Existing explicit bar lists need `clipboard` added to one region; placing it in two regions is invalid. Search is case-insensitive over full text; the picker displays up to 50 matching entries, newest first, with bounded previews. Up/Down selects an entry and Enter reselects it, then closes the picker so you can paste normally. Clicking an entry does the same. Delete removes one item, Clear history removes all, and Escape/Close/outside click dismiss the picker. Reselect never types into another application. `cabby clipboard-status` reports backend/count/byte status without content; `cabby clipboard-clear` clears history.

The coordinator's private socket carries typed list/select/delete/clear requests. List replies contain bounded previews only. The desktop activation socket accepts small commands, uses exclusive ownership and 0600 permissions, and removes its endpoint on graceful subscription cleanup. The default runtime root is `$XDG_RUNTIME_DIR/cabby-shell`; a managed `active.toml` beside a coordinator `owner.lock` uses that snapshot's parent. The existing `--runtime-dir` CLI option targets that coordinator. A standalone desktop uses the standard runtime root. No content is written to runtime snapshots: `clipboard.json` contains only revision/state/count. GUI debug output redacts messages and entries.

## Retention and transport

Defaults are enabled, 50 items, 4 MiB per item and 32 MiB of retained encoded payloads. [Configuration](configuration.md#clipboard) documents each bound, interactions and live reload; [clipboard.toml](../examples/config/clipboard.toml) and the [disabled alternative](../examples/config/clipboard-disabled.toml) are runnable examples. Smaller limits trim retained history immediately. Invalid config preserves the previous policy. Coordinator restart loses history; desktop restart does not. Disabling clears memory and releases Cabby's current selection; external selections remain owned by their source.

The pinned niri baseline exposes `ext-data-control-v1`, which allows event-driven monitoring and ownership without focus or command polling. Cabby binds the first advertised seat and leaves primary selection alone. Missing protocol/seat and connection loss produce explicit status and a two-second reconnect delay. Physical multiple-seat behavior is unsupported by this initial policy; it never silently combines primary selection or every seat.

Supported offers are UTF-8 text (`text/plain;charset=utf-8`, its uppercase UTF-8 alias, `UTF8_STRING`, or `text/plain`) and PNG images, with PNG preferred when both exist. Other representations, HTML-only/file lists, malformed UTF-8/NUL text, empty payloads, malformed images and oversized transfers are skipped. Their source is not replaced. A supported completed transfer is retained and re-offered by Cabby, so it remains pasteable after its original source exits. Byte-identical copies deduplicate and move to the front. A per-coordinator MIME marker prevents reselection feedback loops. Deleting/clearing a currently owned item destroys only Cabby's source, avoiding an unconditional clear of a newer external selection.

An offer advertising `x-kde-passwordManagerHint` is skipped before receiving any payload, regardless of the hint value. This is a conservative available hint, not a secret detector; applications can copy credentials without it. No persistence, clipboard synchronization, primary-selection history or automatic paste injection is implemented.

Transfers use nonblocking close-on-exec pipes/FDs, a three-second deadline, one incoming transfer and at most eight outgoing sends. Work per dispatch and offer/MIME counts are bounded. Commands expire before the IPC timeout instead of applying late. Retained-byte limits are not process RSS limits: metadata, buffer capacity, the current owned source, pending sends and bounded image decoding allocate additional memory. PNG validation caps dimensions at 8192 per axis, 16,777,216 pixels and 64 MiB of decoder allocation. No clipboard helper processes are needed in production.

## Acceptance

Policy tests cover retention, deduplication, search, malformed text/images, redacted Debug and MIME sensitivity/own-source filtering. Nested source/consumer clients use `wl-copy`/`wl-paste` only against a private compositor, verifying source exit, reselection, PNG bytes, desktop-stop ownership, large/unsupported rejection, delete/clear and reload/disable. The picker runs through the actual desktop activation endpoint with keyboard focus and pixel checks on hardware Vulkan and software. Runtime files and logs are checked for fixture payloads. These are isolated observations, not physical multi-seat or every application's MIME compatibility evidence.
