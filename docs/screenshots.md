# Screenshots

Run `cabby screenshot` for a region, or `cabby screenshot-monitor` for the whole focused output. The optional `screenshot` bar contribution uses its clicked output. The existing desktop process hosts the workflow; no extra unit or installed binary is needed.

A supervised grim child first captures the selected output into memory, while the screenshot surface remains unmapped. The selector and its controls render only after capture completes, over that frozen source image. Drag a region to open its preview, or choose Monitor. The preview supports Copy, Save, Cancel and Select region (returning to the original frozen image). Repeated activation reuses this image rather than capturing the selector. Once the selector/preview opens, Escape and Cancel dismiss it; outside click dismisses the preview. `cabby screenshot-cancel` also cancels a pending capture. Output change/removal cancels the workflow. Explicit Save uses a generated editable PNG filename in the configured directory; Copy keeps the preview open.

[Configuration](configuration.md#screenshot) documents `screenshot.directory` (default `$HOME/Pictures/Screenshots`) and `screenshot.include_cursor` (default false). Nonempty relative directories resolve against the config file. Directory changes affect the next Save in an existing preview; pointer inclusion affects the next capture. Theme/font changes apply live; renderer restart discards unsaved captures. Niri's existing screenshot-window action remains available independently.

## Ownership, bounds and privacy

Pixels remain in memory until explicit Save. Clipboard copy sends a sealed close-on-exec anonymous memory FD over the coordinator's private socket; no PNG temporary path is created. The clipboard service validates FD sealing, regular-file type, encoded size and PNG content before taking ownership. Clipboard must be enabled/available and its per-item size limit still applies; a failed copy leaves the preview available. Coordinator-owned selection survives closing the screenshot UI.

Grim uses explicit argument arrays, bounded stdout (32 MiB), discarded stderr and a five-second timeout. Cancel kills and reaps the helper; a parent-death signal and the desktop service cgroup cover abrupt host failure. A single background work permit serializes image decode/crop. Images are capped at 8192 per axis, 16,777,216 pixels and 64 MiB of decoder allocation. Additional source/preview/render textures and encoding buffers consume bounded memory beyond that decode budget. Diagnostic Debug output hides pixel bytes and filenames.

Selection coordinates are local to one output. Crop endpoints clamp to the logical surface and map into the actual oriented PNG dimensions using floor/ceil bounds. This handles reverse drags, fractional scale and transformed outputs without guessing global physical rectangles. The current workflow operates on one output at a time; choose another output through its bar button or compositor focus before starting. Physical multiple-output/input behavior remains unverified.

Save creates a private 0600 PNG without replacing an existing file. It writes/syncs an anonymous same-directory `O_TMPFILE`, then atomically links the completed file into place. Failure, cancellation before publication or process loss leaves no named partial image. Filesystems without this Linux mechanism, denied/full directories, invalid filenames and existing destinations produce a clear error and retain the preview. Already published files are explicit saves and remain after Cancel. Filename editing accepts a single `.png` name, not a directory path. Parent directories are created only on Save; existing directory permissions are preserved.

`screenshot.json` is disposable 0600 metadata: state/action, busy/error status, PID and logical/source/selected dimensions. It contains no pixels or filenames. `cabby screenshot-status` reads this metadata. Closing resets idle state; desktop startup clears crash-stale status. Direct unmanaged crash metadata can remain until restart/session cleanup. Capture/clipboard content never enters logs, config, runtime image files or a cache.

## Acceptance

Rust fixtures test geometry, PNG crop bytes, atomic/no-overwrite/cancelled saves, helper bounds/failure/timeout/cancellation/reaping and literal arguments. Clipboard socket tests verify sealed FD transfer, close-on-exec and fragmented ordinary commands. Nested GPU/software tests use an isolated virtual pointer to drag real controls, copy/paste exact PNG bytes, save, reject overwrites, cancel without a file, rotate/fractionally scale outputs and cancel stale geometry. Known solid pixels prove the selection overlay is excluded. Malformed/unsealed FD imports are rejected without replacing the clipboard. No live desktop capture, clipboard mutation or physical output change is used for acceptance. The software renderer currently paints the preview backdrop opaque black; the frozen image and controls remain usable. Vulkan is the tested primary renderer.
